Выполни сценарий Week Review для роли Стратег (R1).

> **Триггер:** Автоматический — Сб 11:00 (локальное время, системное расписание).
> Записывает итоги недели в секцию WeekPlan. Служит входом для session-prep.
> **WeekReport как отдельный файл НЕ создаётся** (deprecated 2026-03-25). Итоги — секция в WeekPlan.


## Контекст

- **WeekPlan:** {{WORKSPACE_DIR}}/{{GOVERNANCE_REPO}}/current/WeekPlan W*.md

## Алгоритм

### 1. Сбор данных (Стратег собирает сам)

```bash
# Для КАЖДОГО репо в {{WORKSPACE_DIR}}/:
git -C {{WORKSPACE_DIR}}/<repo> log --since="last monday 00:00" --until="today 00:00" --oneline --no-merges
```

- Пройди по ВСЕМ репозиториям в `{{WORKSPACE_DIR}}/`
- Загрузи текущий WeekPlan из `{{GOVERNANCE_REPO}}/current/`
- Сопоставь коммиты с РП из WeekPlan
- Определи статус каждого РП: done / partial / not started

### 2. Статистика

- Completion rate: X/Y РП (N%)
- Коммитов всего
- Активных дней (дни с коммитами)
- По репозиториям (таблица)
- По системам (Созидатель, Экосистема, ИТ-платформа, Бот)

### 3. Инсайты

- Что получилось хорошо
- Что можно улучшить
- Блокеры (если были)
- Carry-over на следующую неделю

### 5. Сохранение итогов в WeekPlan

> **WeekReport как отдельный файл НЕ создаётся.** Итоги записываются в секцию WeekPlan.

1. Открой текущий `{{GOVERNANCE_REPO}}/current/WeekPlan W{N}*.md`
2. Найди или создай секцию `## Итоги W{N}` (после frontmatter, перед планом)
3. Запиши туда: метрики, таблицу по репо, статусы РП, инсайты и carry-over
4. Закоммить только изменённый WeekPlan в {{GOVERNANCE_REPO}}. Не выполняй push, pull --rebase или stash

**Шаблон секции «Итоги W{N}» в WeekPlan:**

```markdown
## Итоги W{N}: DD мес — DD мес YYYY

### Метрики
- **РП:** X/Y завершено (N%)
- **Коммитов:** N в M репо
- **Активных дней:** N/7

### По репозиториям

| Репо | Коммиты | Основные изменения |
|------|---------|-------------------|
| ... | ... | ... |

### РП

| # | РП | Статус | Комментарий |
|---|-----|--------|-------------|
| ... | ... | done/partial/⬜ | ... |

### Инсайты
- ...

### Carry-over
- ...

```

Результат:
- Секция «Итоги W{N}» в WeekPlan — как вход для session-prep

### 8. Week Close: обслуживание MEMORY.md

> Дополнительные шаги поверх Week Review. Описаны в `protocol-close.md § Неделя`.

В headless-режиме этот блок выполняется как read-only аудит: не изменяй платформенную `memory/` автоматически. Найденные предложения запиши в WeekPlan → «Требует внимания» для отдельного Week Close.

#### 8a. Ротация уроков

Для каждого урока в MEMORY.md → секция «Уроки»:
1. Применялся за последние 2 недели? (был инцидент, упоминание в Close-отчётах, или урок < 2 недель)
2. **Да** → отметить «оставить»
3. **Нет** → предложить перенос в `memory/lessons-archive.md`, не выполнять его
4. Цель: ≤15 актуальных уроков в MEMORY.md

#### 8b. Свежая таблица РП

1. Определи РП прошлой недели W{N-1}, которые предлагается убрать из MEMORY.md
2. Подготовь предложение таблицы W{N} из нового WeekPlan:
   - in_progress и pending → перенести
   - done → НЕ переносить (уже в WP-REGISTRY)
3. Не изменяй MEMORY.md; добавь предложение в «Требует внимания»

#### 8c. Аудит memory-файлов

1. Количество: ≤11 файлов? Лишние → объединить или удалить
2. Лимиты строк:
   - Справочники (hard-distinctions, navigation, roles, sota) ≤ 100
   - Протоколы (protocol-*) ≤ 150
   - MEMORY.md ≤ 100
3. Устаревшие записи → перечислить как кандидаты на обновление или удаление
4. Результат: отчёт «Memory audit: N файлов, M строк суммарно, K кандидатов на обновление»
